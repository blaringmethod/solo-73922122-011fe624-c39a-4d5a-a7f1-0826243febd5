# 馆藏著录复核 · 双组抽样与 Horvitz–Thompson 估计

两份名录（展出名录、待修复清单）常有同一件藏品。两组馆员各自独立等概率、
不放回抽签复核，本应用用 **Horvitz–Thompson（HT）法**估计两份名录合起来
著录有误的藏品总数及抽样标准误。

## 启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

数据存放在命名卷 `review-data` 中的 SQLite 文件 `/data/review.db`，
容器重启后数据保留；`docker compose down -v` 可连同数据卷一起清除。

本地不使用 Docker 时：

```bash
pip install -r requirements.txt
APP_DB_PATH=./review.db python wsgi.py        # 开发服务器
# 或
APP_DB_PATH=./review.db gunicorn -b 0.0.0.0:8000 wsgi:app
```

## 演示流程（约 2 分钟）

1. **导入与锁定**：打开「导入与锁定」，点「填入内置演示数据」→「校验导入并锁定」。
   首次登记后两份名录与中签号即锁定，不能再次导入（总览页可「清空并重置」用于重新演示）。
   演示数据：甲名录 12 件抽 7 件、乙名录 10 件抽 5 件，重叠 6 件，并集 16 件；
   C009、C011 同时被两组抽中；C012 在两份名录中题名不同（同号两件），仅甲组抽中。
   两份名录的原始行（各自题名）也会保存，拆分/并回页面可回看。
2. **两组登记**：分别在「甲组登记」「乙组登记」点「一键填入演示结论」，
   也可逐件选择「有误/无误」并备注；整表一次保存，更正自动写审计。
   预置数据中 C011 两组结论冲突（甲说无误、乙说有误）。
3. **待核清单**：结论未补齐、或同号藏品两组结论冲突时，只列这些待核藏品。
   同一页下方「共有编号拆分 / 并回」列出两份名录共有的编号。
4. **拆分同号两件**：在待核页把 C011（或 C012）「拆为甲、乙两件」。
   拆分后甲件只归甲名录、乙件只归乙名录，各自沿用本组中签号与登记；
   两组原名录、中签号与登记原样保留，两件各自判定待核。拆开后 C011
   的甲件（无误）与乙件（有误）不再互相冲突，待核清单即清空。
   出数页会按拆分后的归属重算 π_i、π_ij、HT 估计与标准误，并把两件分别
   列入逐件明细。
5. **并回**：在待核页点「并回同号」。两件并回后若两组结论冲突，会重新
   列入待核并提示核对；两组各自的登记始终不丢。
6. **出数**：出数页展示 HT 估计、标准误、近似 95% 置信区间、逐件 π_i 与
   联合概率明细；点「固化为出数时点快照」保存同一时点的登记与结果。
   页面携带本次取数的状态修订号；若取数之后拆分状态或任一登记变过
   （即使又改回原值），保存会被拒绝并提示刷新，快照列表不新增记录。
   快照会注明当时拆开的共有编号，旧快照始终可回看。

## 统计方法

设两组各自在名录内做独立的不放回简单随机抽样（SRS），总体为两份名录
去重并集 U，藏品 i 用 (a_i, b_i) 标记是否属于甲/乙名录。
馆员把共有编号拆为甲、乙两件后，甲件记 (1,0)、乙件记 (0,1)，各按单组
归属计算；并回后恢复同号只算一件、按 (1,1) 计算。

- 一阶入样概率（i 至少被一组抽中）：
  π_i = 1 − (1 − a_i·n_A/N_A)(1 − b_i·n_B/N_B)
- 二阶联合入样概率 π_ij = P(S_i ∩ S_j)，用容斥计算：
  π_ij = 1 − P(S_iᶜ) − P(S_jᶜ) + P(S_iᶜ ∩ S_jᶜ)，
  其中组内 SRS 的联合入样概率为 n(n−1)/(N(N−1))，两组间按独立性相乘。
  拆分后 π_i=0 的藏品（不属任何被抽样名录）不进入可估计总体；π_ij
  理论为 0 的对在明细里注明「不可同时入样」并按 0 计交叉项。
- HT 总量估计：Ŷ = Σ_i y_i/π_i（y_i=1 表示著录有误）
- HT 代入式方差估计：
  V̂ = Σ_i (1−π_i)/π_i²·y_i + Σ_i Σ_{j≠i} (π_ij−π_iπ_j)/(π_ij·π_i·π_j)·y_i·y_j
  标准误 SE = √V̂。**当 V̂ 为负时，页面与快照均注明「标准误不可用」**，
  不展示置信区间。

公式实现（`app/stats.py`）已通过全样本空间精确枚举验证：对 3 件藏品
×4 种归属组合 ×全部可行抽签量共 159 个配置，以及 77 个更大规模随机配置，
π_i、π_ij 与穷举真值逐一吻合；HT 点估计与方差估计在全部抽签组合上的
期望分别等于真实总量与真实抽样方差（无偏性）。

## 业务规则对照

- 每组抽签 2–200 件，组内等概率、不放回；导入时校验编号去重、
  中签号必须在对应名录内，违规即拒绝并提示。
- 首次导入即锁定名录与中签号；登记结论可随时更正，每次变更写
  `reg_audit` 审计表（原值、新值、时间）。
- 出数以同一时点读取的登记为准；同号藏品只算一件（并集表主键去重）；
  存在未补齐或冲突结论时禁止出数。
- **共有编号拆分 / 并回**：只增加或删除 `item_splits` 标记，不改
  `items`、`draws`、`registrations`，两组原名录、中签号与登记始终保留；
  拆分/并回每次操作写 `split_audit`。拆分后甲件、乙件分别判定待核，
  并按更新后的归属重算 π_i、π_ij、HT 估计与标准误；并回后若两组结论
  冲突，该编号重新列入待核。
- **快照时点校验**：`meta.revision` 单调递增，拆分、并回和任何结论变化
  （包括改回原值）都会 +1。出数页把本次取数的修订号作为令牌随表单提交；
  保存时先比对令牌，再在同一事务内复核修订号后写入。不一致即拒绝保存
  并提示刷新，快照列表不新增记录。快照 payload 记录 `split_ids`
  （当时拆开的编号）与 `revision`，旧快照按 payload 原样展示，不受
  后续并回影响。
- 出数读取在一条只读事务内完成（WAL 下并发登记/改判不被阻塞，其提交
  在本次读结束后才可见），保证结果与登记来自同一已提交状态。

## 测试

```bash
python -m unittest discover -s tests -v
```

共 30 个测试，覆盖统计公式精确枚举、HT 无偏性、负方差分支、
导入校验、从导入到出数快照的完整 Web 流程，以及同号拆分/并回：
拆开后两件分别待核、按新归属重算 π/HT/SE、往返拆分无损、快照记录拆分
编号且旧快照可读、取数后改判（含改回原值）或先拆后并回时拒绝保存。

## 已知限制

- 面向单机构演示规模（每份名录 ≤200 件），未做用户登录与权限分组，
  两组馆员的操作权限由页面入口区分，没有账号级隔离。
- 置信区间为正态近似，未做对数变换或小样本修正。
